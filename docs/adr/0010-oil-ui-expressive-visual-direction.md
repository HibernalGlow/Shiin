## 背景与问题

Shiin 目前的桌面端和 Xaihi 面板仍以早期 MD3 / MD3 Expressive 壳层为主：

- 壳层、标题栏、侧栏、节点面板和按钮共享 `src/ui/md3e.tsx` 的旧 token 与组件语法；
- 默认的深色青柠配色、标准卡片边界和统一圆角已经成为视觉主角，无法体现 Shiin 的截图、手柄和摄影器材语境；
- 当前实现把“Expressive”理解成换色、随机形状和圆角变化，页面构图仍接近后台模板；
- [ADR-0002](./0002-frontend-react-migration-and-md3-expressive.md)、[ADR-0007](./0007-expressive-controls-and-selects.md)、[ADR-0008](./0008-tonal-palette-from-single-seed.md) 中关于 MD3 的视觉约束需要重新评估。业务功能、React 技术栈、Xaihi 节点契约和共享核心不因本 ADR 改变。

用户要求彻底重写 UI，旧 MD3 视觉不得继续作为默认外观。用户指定使用 Oil UI 的方向探索流程，先比较三套首屏方向，再选定一套进入完整实现。

## 产品识别与设计基线

### 品类与主要任务

Shiin 是桌面截图与即时回放工具，属于高频使用的创作工具 / 游戏辅助工具。用户打开首屏主要做三件事：

1. 立即截图；
2. 查看手柄、监听和捕获管线是否就绪；
3. 在需要时处理权限、保存目录、组合键和 OBS 回放。

首屏应先让用户看到“现在能不能按下快门”，再让用户进入完整配置。配置和权限是工作流的一部分，不能被放在装饰性的介绍之后。

### 参考项目提取的关系

从 Inkloom 和 HibernalGlow CV 项目保留以下关系：

- 首屏由一个清楚的主动作承担焦点，大字只服务于当前任务；
- 内容直接落在纸面或场景上，避免一层层相同的卡片；
- 圆角按角色变化，连接式控件用外圆角 + 内小圆角表达“接合”；
- 形状、颜色和动效是独立轴，同类控件保持一致，不把一个形状复制到整页；
- 反馈沿同一条路径传递：按下快门、捕获完成、文件写入和提示应形成一个连续动作；
- 字体与间距优先保证中文长标题、状态说明和数字在实际窗口中可读。

### 配色参考的可用信息

用户提供的配色图给出了可复用的色彩关系，而不是要求复制角色立绘或业务内容：

| 角色 | 色值 | 在 Shiin 中的候选用途 |
| --- | --- | --- |
| 荧光青柠 | `#C8F000` | 主快门动作、监听中的即时反馈、关键形状 |
| 橄榄卡其 | `#85864A` | 器材语境、次级状态、辅助导航 |
| 暖米白 | `#F2F0E8` | 纸面、截图预览、浅色内容底 |
| 沙色 | `#D0C6AD` | 次级容器、输入区和已完成状态 |
| 装备墨灰 | `#343831` | 深色工作区、日志、设备信息 |
| 领带暗红 | `#A72D3B` | 错误、危险操作、快门完成后的强调反馈 |

以上颜色已随方向 A 采纳；正文、容器、描边、禁用态和深浅背景上的配对色由 `src/ui/expressive-theme.ts` 统一定义。Oil UI 是设计参考与工作流程，不是产品品牌；界面仍使用 Shiin 名称，不出现技能名称和内部方案名称。

## 探索记录：三套方向

以下三套方案共用同一组真实任务和文案，首屏骨架、字体、色彩身份和主视觉分别拉开。三套方案都放弃旧 MD3 的深色青柠后台壳层、统一卡片网格和“所有组件同一圆角”语法。

### 方向 A：荧光器材台

**北极星**：让用户一眼看到“快门已经接通”，像在一张铺着器材的工作台上按下实体快门。

**调性**：能量高、完成度中高、密度中高、分量重、严肃度中等。依据是手柄与摄影工具需要快速识别和明确状态，不能像作品集一样过度留白。

**生成引擎**：户外摄影器材台。把参考图中的荧光青柠、橄榄卡其、装备墨灰和暗红转成器材标签、接线节点和状态块，保留材质关系，不搬运角色立绘。

**首屏骨架**：用户先看当前监听状态和快门动作；主区不是左右两张卡，而是一张贯穿页面的器材台面。

```text
┌─────────────────────────────────────────────────────────────┐
│ Shiin / 当前监听                         权限  缩放  语言   │
├───────────────┬─────────────────────────────────────────────┤
│ 设备与动作     │  [荧光快门圆盘]  捕捉这一帧                 │
│ 监听状态       │  ───── 接线：手柄 → 捕获 → 文件/回放       │
│ 权限 / 设置    │  当前设备、目标窗口、最近结果               │
│                 │  [立即截图] [开启监听] [保存回放]           │
└───────────────┴─────────────────────────────────────────────┘
```

**字体**：`Roboto Flex` 或系统无衬线用于正文和状态；展示标题使用较重字重（760–860），数字使用等宽数字。中文采用 `PingFang SC / Hiragino Sans GB / Microsoft YaHei` 回退栈。

**色彩**：底色 `#F2F0E8`，主动作 `#C8F000`，深色工作区 `#343831`，次级状态 `#85864A`，危险与错误 `#A72D3B`，容器浅色 `#D0C6AD`。荧光色只占主动作和关键图形面积，不铺满全部背景。

**主视觉**：一个不规则荧光青柠“快门盘”，周围连接三个真实对象：手柄、捕获目标、输出位置。连接线在监听状态下流动，截图完成时沿输出方向收束。

**图标**：继续使用现有 AppIcon 轮廓体系，统一 1.5–1.75px 描边；品牌快门盘使用少量专属几何形状。

**控件语法**：主按钮是宽大的异形块，默认外角 28px，按下时收缩为更紧的 12px；次级按钮是连接组，外侧 24px、内部 8px；状态块使用短标签和色块，不使用胶囊包裹每一行文字。

**动效**：拟声词“咔哒”，像相机快门和器材卡扣。首屏首次进入时先落下快门盘，再让接线和状态信息跟上；按下截图时快门盘压缩、输出节点亮起；监听开关切换时连接线从输入端向输出端接合。`prefers-reduced-motion` 下直接到位。

**结构性突破**：用一条横跨主区的连接轨代替后台常见的卡片网格，让“输入—捕获—输出”成为阅读顺序。

**记忆点**：截图完成时，荧光盘的形状短暂收束为文件输出节点，随后恢复主形状。

**放弃什么**：放弃全页紫色纸面、每项独立圆角卡片、装饰性渐变和无意义的指标数字。

### 方向 B：紫色纸面接合台

**北极星**：让复杂的截图配置像一张可以直接操作的工作纸，重点关系通过形状和空间接起来。

**调性**：能量中等、完成度高、密度中低、分量中等、严肃度中等偏活泼。依据是 HibernalGlow CV 的“可追溯工作台”方向，适合把状态和配置同时放在首屏。

**生成引擎**：淡紫纸面上的节点工作台。借用参考项目的开放构图、紫色主动作、绿色/桃色语义容器和变化圆角，避免直接复制作品集的页面结构。

**首屏骨架**：用户先看到一个大号“立即截图”动作，右侧是可变形的捕获链；配置不再按普通表单顺序堆叠，而是按“来源—动作—结果”分组。

```text
┌─────────────────────────────────────────────────────────────┐
│ Shiin                                  当前状态 · 监听中     │
├──────────────┬──────────────────────────┬───────────────────┤
│ 目的地         │ 大标题：捕捉这一帧        │ 连接工作台         │
│ 工作台         │ 说明 + [立即截图]         │ 手柄 ◇ 捕获 ◇ 输出 │
│ 权限           │ 最近结果                 │ 动作与状态           │
│ 设置           │                           │                     │
└──────────────┴──────────────────────────┴───────────────────┘
```

**字体**：`Google Sans Flex` / `Noto Sans SC`，标题 52–76px、正文 15–17px、状态和数字 12–14px。标题与正文共享左侧基线，中文标题行高 1.18–1.28。

**色彩**：底色 `#F7F3FC`，主色 `#6244B6`，主容器 `#E9DDFF`，绿色状态容器 `#D9EDC0`，桃色提示容器 `#FFDCCB`，深色日志 `#292236`，描边 `#CCC3D7`。色彩关系沿用参考 CV 项目，整体不再使用旧的青柠深色壳层。

**主视觉**：右侧一组不同角色形状组成的“接合链”，每个角色只服务一个对象：主快门、设备、捕获目标和输出。

**图标**：现有 AppIcon 作为通用图标；主快门和工作台连接点用低数量的专属形状，不给每个标题都加图标。

**控件语法**：主按钮为紫色大块，悬停时圆角从 32px 变为 18px；互斥选项使用连接式组；输入区域用浅紫表面和一条清晰描边，选中项移动一块背景板。

**动效**：拟声词“接上”，像磁铁吸合。首次进入时主快门先出现，工作台形状后接合；切换目的地时选中底板滑动到新项；截图完成时输出节点沿连接方向亮起。视图切换用 350–450ms 的遮罩式过渡。

**结构性突破**：右侧工作台不是装饰图，而是当前配置的实时结构图；它同时展示状态、主动作和结果路径。

**记忆点**：主动作与状态链共享同一组形状角色，按下截图时从快门形状自然变为输出形状。

**放弃什么**：放弃暗色终端、彩色发光圆晕、普通 SaaS 卡片网格和重复的全大写英文眉标。

### 方向 C：暗房红线

**北极星**：把截图当作一次需要确认的现场记录，界面像暗房里的控制台，安静、迅速、结果明确。

**调性**：能量中低、完成度高、密度高、分量重、严肃度高。依据是截图和录制发生在游戏或创作现场，用户需要低干扰、高对比的持续状态。

**生成引擎**：暗房控制台与胶片检视窗。借用参考图的装备墨灰、暗红和暖米白关系，暗红只承担快门完成和危险操作，不做泛滥的霓虹装饰。

**首屏骨架**：不使用左栏加卡片网格。首屏是一个横向控制台：顶部是当前目标与状态，中央是当前帧/捕获动作，底部是可折叠的设备与输出抽屉。

```text
┌─────────────────────────────────────────────────────────────┐
│ SHIIN / FRAME 0142                         ● READY           │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│              [当前捕获目标 / 大型快门视窗]                  │
│                    [快门]  [监听]                           │
│                                                             │
├───────────────────────┬───────────────────────┬─────────────┤
│ 手柄 · 已连接          │ 目标 · 全屏 DXGI      │ 输出 · PNG  │
└───────────────────────┴───────────────────────┴─────────────┘
```

**字体**：标题使用 `IBM Plex Sans` 或系统无衬线 700–800，数据和日志使用 `IBM Plex Mono` / 系统等宽；中文正文保持 14–16px 和 1.65 行高。

**色彩**：底色 `#20211F`，主动作 `#A72D3B`，正文 `#F2F0E8`，次级表面 `#343831`，状态辅助 `#85864A`，完成提示使用高亮暖米白，不使用荧光绿大面积铺底。浅色预览窗使用 `#F2F0E8`，形成暗房中的纸面反差。

**主视觉**：中央检视窗显示当前捕获目标和一个红色快门刻度；设备、目标、输出以三条底部状态带呈现。

**图标**：使用现有 AppIcon 的紧凑描边，允许少量字符标记（`REC`、`READY`、帧号）承担信息，不给每个状态配独立圆形图标。

**控件语法**：按钮为短而重的矩形块，圆角 8–16px；选中状态用一条移动的底部标尺或整块暗红底；日志和设备信息使用等宽数字与细分隔线。

**动效**：拟声词“落片”，像快门帘和胶片压入检视窗。主快门按下时视窗短暂收暗、红色刻度落下，结果写入后恢复；状态抽屉从底部阻尼滑入；错误沿红色状态带向左收束。减少动态时只保留颜色和内容变化。

**结构性突破**：以一个持续存在的中央检视窗代替后台页面的英雄卡片，底部抽屉承载配置，用户不离开当前帧即可调整目标。

**记忆点**：截图完成不是 toast 飘出，而是中央检视窗交付一帧编号和输出路径。

**放弃什么**：放弃大面积渐变、圆形浮动按钮、浅色卡片套卡片和过多装饰形状。

## 差异检验

| 项目 | 方向 A | 方向 B | 方向 C |
| --- | --- | --- | --- |
| 首屏骨架 | 横向器材台 + 连接轨 | 左导航 + 大动作 + 右侧工作台 | 中央检视窗 + 底部抽屉 |
| 字体气质 | 厚重无衬线 + 等宽数字 | 可变无衬线 + 宽松中文 | 工业无衬线 + 等宽日志 |
| 色彩家族 | 荧光青柠 / 橄榄 / 装备灰 / 暗红 | 紫色纸面 / 绿色 / 桃色 | 暗灰 / 暗红 / 暖米白 / 橄榄 |
| 主视觉 | 荧光快门盘与接线 | 角色形状接合链 | 暗房检视窗与红色刻度 |
| 品类套路突破 | 连接轨替代卡片网格 | 工作台同时表达状态与配置 | 检视窗替代英雄卡片，配置下沉为抽屉 |

三套方案的首屏骨架、字体、色彩家族和主视觉均不重复；方向 A 取最高能量，方向 C 取最高分量，方向 B 作为参考项目关系最完整的平衡方案。

## 采纳决定与修正（2026-10-22）

用户选定 A「荧光器材台」，吸收 B/C 的布局优点并增加 Motion 操作反馈。用户随后否定了首轮主页和权限页的执行效果：大型暗色器材面板挤走配置、权限不应独立占用 tab、手机底栏不应继续沿用旧 MD 外观。本节为当前有效决定，前文三套方向保留为探索记录。

**后续反馈**：本节中的顶部 primary tabs 已被用户否定。导航与三档布局以文末「Rhythm 参考与下一轮结构方案」为准；其余已采纳的配色、权限归属与状态真实性约束继续保留。

- 保留 A 的暖纸面、荧光主动作和设备色彩关系，取消大型暗色 hero、装饰性输入输出节点、重复品牌和侧栏截图动作。
- 从 B 保留相连控件、可直接编辑的来源与输出；从 C 保留结果交付清晰、操作常驻的优点，不再照搬大型中央检视窗。
- 只设「工作台」「设置」两个目的地，使用顶部 primary tabs。权限属于设置中的可展开访问列表；标题栏和缺权限提示直接定位、展开该区域，不创建独立权限页，不因首次缺权限强制换页。
- 桌面工作台由紧凑快门区、来源与输出、触发组合、自动化与实时测试组成。主配置直接出现在首屏。
- 小于 600px 时改为单列，底部为通栏 contextual action bar，提供截图、监听、回放，并计入 `safe-area-inset-bottom`。导航仍在顶部，避免把两个目的地套入三至五目的地的旧底部导航。
- 采用 Material 语义色角色、8px 基础间距与自适应 pane；连接组使用外大内小的圆角，选中项以形状和色调共同区分。
- 继续使用原有控件中有效的交互与形状偏好数据。`md3e-shapes.ts` 保留为几何数据与持久化契约，不导入旧 `md3e.tsx` 壳层。
- Oil UI 只用于方向探索和截图评审。产品源码中删除 Oil 的文件、函数、类、变量和测试标识命名，主题入口为 `expressive-theme.ts`，品牌始终为 Shiin。
- 权限检测失败显示真实错误，不再回退成「全部已授权」。设置按顺序持久化；失败保留输入并提供重试，成功后可重新读取。

### 动效契约

采用项目已声明的 Motion for React（`motion/react`），不引入整套 React Bits。

| 触发 | 可观察变化 | 状态约束 |
| --- | --- | --- |
| 进入工作台 | 紧凑快门区域轻弹到位 | 只在挂载时发生，不因轮询重播 |

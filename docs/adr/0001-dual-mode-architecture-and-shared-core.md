# ADR-0001: 架构分层与双模态运行（共享核心 + 独立桌面应用 + Xaihi 插件）

- **状态**：提议中 (Proposed)
- **日期**：2026-10-19
- **相关方**：Shiin 开发组 / Xaihi 生态

---

## 背景与问题

现有的游戏截图工具（Shiin / GamePad-ScreenShot-Windows）是一个专为桌面端设计的应用，依赖 Electron + Vue 3，功能逻辑（手柄监听、截图、OBS 联动、配置管理等）深度耦合在 Electron 主进程（`background.js`）与 Vue 单文件组件中。

当前需求要求：
1. 项目必须能独立发布为普通桌面应用（无需安装 Xaihi）；
2. 同时必须能作为标准插件直接安装进 Xaihi 宿主，以标准节点形式运行；
3. 两套运行模式必须共享核心业务逻辑，杜绝维护两套分支或冗余复制业务代码。

## 决策

我们决定建立三层解耦架构：

1. **共享核心层 (`src/core/`)**：
   - 包含手柄输入轮询与事件处理、屏幕与窗口捕获、图像编码、OBS 控制、按键序列判定、配置模型与文件名模板格式化。
   - 核心层为纯 Node.js / TypeScript 模块，不引入任何 Electron GUI、Vue、React 或特定框架上下文。
   - 所有外部操作（如播放音效、显示系统通知、读取屏幕源）通过接口回调（Adapter Interface）抽象。

2. **独立应用宿主层 (`src/app/`)**：
   - 保留 Electron 外壳，负责窗口创建、托盘菜单、开机自启、本地文件对话框、单实例锁。
   - 拥有轻量 CLI 与 TUI 入口，可在纯终端环境下运行。
   - 通过 IPC 适配器为独立应用前端提供与渲染进程的通信通道。

3. **Xaihi 插件宿主层 (`src/xaihi/`)**：
   - 遵循 Xaihi 插件体系的 Cordis 服务与 `defineNode` 契约。
   - 将共享核心动作（截图、枚举设备、开关监听、OBS 回放）包装为节点动作（Actions）及斜杠命令（`/shiin`）。
   - 生命周期完全绑定宿主上下文，在插件卸载或宿主退出时通过 `ctx.effect` 清理手柄轮询与系统钩子。

## 权衡与后果

- **正面**：核心能力单一真源，无论在独立桌面还是 Xaihi 插件中表现完全一致；测试可以在无桌面环境下对 `core` 单独跑自动化单元测试。
- **代价**：原本在 Electron 主进程中直调的代码需要通过抽象接口层解耦，初期重构工作量稍有增加。
